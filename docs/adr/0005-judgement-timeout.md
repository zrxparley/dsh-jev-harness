# ADR 0005 · 判定超时保持默认 800ms

- 状态：已接受
- 日期：2026-11-19
- 关联：#39（失败模式）、#37（jev/auto adapter）

## 背景

#39 要求「判定超时与生成超时分开，判定默认 800ms；超时后不再等待，直接兜底」。
本地 shim 试跑曾把判定超时临时改成 4000ms，需要留下依据，避免以后误以为
仓库默认值已经改了。

## 实测数据

测量方式：`POST https://api.typesafe.ai/v1/systemone`，`choice` 题，criteria 与
`criteria.js`（`CRITERIA_VERSION=1.0.0`）逐字一致，不经过 shim、不带上游模型。

20 次采样（`shim/measurements/jev-latency-20261120.md`）：

| 指标 | 值 |
|---|---:|
| min | 292 ms |
| p50 | 334 ms |
| p95 | 731 ms |
| max | 1283 ms |
| mean | 420 ms |
| > 800 ms | 1 / 20 |
| > 4000 ms | 0 / 20 |

更早的 5 次预热采样为 1237 / 1274 / 1382 / 1899 / 2894 ms（p50 1382），
与上面这批相差一个量级，说明该网关延迟波动很大。

## 决策

1. **代码默认保持 800ms**（`#39` 原文）。20 次里有 1 次超时，超时按设计降级，
   不为此放宽默认值。
2. **4000ms 只作为本地 shim 的运行时覆盖**（`JEV_SHIM_JEV_TIMEOUT_MS`），
   不进仓库默认值、不写进 provider 配置。
3. 判定超时与生成超时分开：判定用 `jevTimeoutMs`/800ms 这一档，生成用 `timeoutMs`。
4. 若后续要把默认值改到 4000ms，需要先补「跨时段、带并发压力」的 ≥20 次采样，
   并证明 p95 仍显著低于新阈值——单批 20 次不足以支撑。

## 后果

- JEV 网关在长尾延迟时，这一轮会降级到默认模型并记 `degraded:true` + `error`，
  面板显示「JEV 未参与 · 已降级」，不会假装成功。
- 用户实际感知是「偶尔一轮没用上判定」，而不是「对话卡住 4 秒」。
